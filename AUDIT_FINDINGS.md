Audit date: 2026-06-09

Scope read before patching: `config.py`, `agent/reward.py`, `train.py`, `agent/train.py`,
`evaluate.py`, `evaluation/metrics.py`, `experiment.py`, `agent/env_wrapper.py`,
`agent/dqn_agent.py`, `detection/feature_extractor.py`, `detection/flow_collector.py`,

`env/attack_simulator.py`, `env/ryu_controller.py`, `isolation/isolator.py`,

## Root Cause 1: reward ablation was not reliably applied

Evidence:

```python
# config.py:198-207
def _build_global_config() -> GlobalConfig:
    cfg = GlobalConfig()
    reward_path = os.getenv("SDNIDS_REWARD_CONFIG")
    if reward_path:
        cfg = replace(cfg, reward=_load_yaml_reward_config(Path(reward_path)))
    return cfg

CFG: GlobalConfig = _build_global_config()
```

Before the patch, the wrapper `train.py` imported `CFG` at module import time and
only set `SDNIDS_REWARD_CONFIG` inside `train()`. Because `CFG` is built once,
setting the env var after `config` has already loaded does not rebuild the reward
object. Local proof in the same process:

```text
initial_normal_reward 1.0
after_env_set_normal_reward 1.0
compute_allow_normal 0.9
```

Impact: RQ2 reward ablation results could reflect default reward/randomness rather
than the selected YAML. This invalidates conclusions such as "v2 is best" until
training starts in a fresh process with the reward env set first.

Fix: `train.py` now launches `python -m agent.train` as a subprocess with
`SDNIDS_REWARD_CONFIG` already set (`train.py:61-76`). `evaluate.py` was changed
the same way so ablation `avg_reward` is computed with the same reward config.

## Root Cause 2: replay buffer learned proposed actions, not executed actions

Evidence before patch:

```python
# agent/env_wrapper.py
raw_action = action
effective_action = self._gate_action(raw_action)
self._apply_action(effective_action)
reward = compute_reward(effective_action, gt)
```

```python
# agent/train.py
action = agent.act(obs)
next_obs, reward, terminated, truncated, info = env.step(action)
agent.remember(obs, action, reward, next_obs, done)
```

The environment executed and rewarded `effective_action`, but DQN replay stored
the original proposed action. If gating converted `block/isolate/flag` into
`allow`, the replay buffer credited the unsafe proposed action with the reward
generated by `allow`. This corrupts Q targets and can produce both collapse modes:
over-isolation when unsafe actions receive normal rewards, and conservative
collapse when attack actions are gated to allow but the policy update is assigned
to the wrong action.

Impact: RQ1 detection performance and RQ2 reward learning are not measuring the
policy that actually interacted with the environment.

Fix: `agent/train.py` now stores `executed_action` in replay and logs both
`proposed_action` and `executed_action` (`agent/train.py:228-249`).

## Root Cause 3: training state missed attack-discriminating features

Evidence:

```python
# detection/feature_extractor.py:56-67
feats["arp_request_rate"] = self._safe_div(self.ctx.arp_request_count, dt)
feats["arp_reply_rate"] = self._safe_div(self.ctx.arp_reply_count, dt)
feats["ssid_beacon_count"] = float(self.ctx.beacon_count)
feats["unknown_ssid_count"] = float(self.ctx.unknown_ssid_count)
```

The counters are only updated by packet callbacks:

```python
# detection/feature_extractor.py:104-109
def on_arp_request(self) -> None: self.ctx.arp_request_count += 1
def on_arp_reply(self) -> None: self.ctx.arp_reply_count += 1
def on_beacon(self, ssid: str) -> None:
    self.ctx.beacon_count += 1
```

But the training environment collects only Ryu REST snapshots:

```python
# detection/flow_collector.py:89-96
snap.flow_stats[dpid] = self._get_json(f"/stats/flow/{dpid}", default=[])
snap.port_stats[dpid] = self._get_json(f"/stats/port/{dpid}", default=[])
snap.arp_table = self._get_json("/sdnids/arp_table", default={})
snap.mac_table = self._get_json("/sdnids/mac_table", default={})
```

No training path feeds `on_arp_reply()` or `on_beacon()` from the simulator into
the `FeatureExtractor`. In a wired Mininet lab, Rogue AP beacon/SSID features are
simulated features, not physical Wi-Fi observations. With these features near
zero, `detection_confidence()` stays low and gating converts detection actions to
`allow`, explaining conservative collapse after the over-isolation fix.

Impact: RQ1 cannot fairly test whether DRL distinguishes normal/attack because
the state vector does not expose the modeled attack signal. RQ3 remains
preliminary because real traffic would need a true packet/feature source.

Fix: `agent/env_wrapper.py` now injects simulator attack features into the lab
state for active ARP/Rogue attacks (`agent/env_wrapper.py:154-183`).

## Root Cause 4: evaluation scenario could be randomized by reset

Evidence before patch:

```python
# evaluation/metrics.py
_start_scenario(scenario, attacks)
obs, _ = env.reset()
```

`SDNIDSEnv.reset()` samples normal-only episodes in training mode:

```python
# agent/env_wrapper.py:185-191
if options and "normal_only_episode" in options:
    return bool(options["normal_only_episode"])
return bool(self.np_random.random() >= self.attack_ratio)
```

Because evaluation used the default training mode, `reset()` could disable the
attack immediately after `_start_scenario()`. Metrics were step-level, but the
scenario control was not deterministic.

Impact: RQ1 evaluation tables could mix intended ARP/Rogue scenarios with
normal-only episodes, and RQ2 reward comparison could be noisy.

Fix: evaluation now resets with explicit `normal_only_episode` and starts attack
scenarios after reset, then refreshes the observation (`evaluation/metrics.py:277-283`).

## Action Path After Patch

1. Agent proposes `proposed_action`.
2. `SDNIDSEnv._gate_action()` may convert it to `executed_action`.
3. Env applies `executed_action` through the isolator.
4. Reward is computed from `executed_action` and step ground truth.
5. Replay buffer stores `executed_action`.
6. `runs/step_debug.csv` logs scenario, ground truth, proposed action, executed
   action, gated flag, reward, target, and done.

## Evaluation Path After Patch

Evaluation uses greedy agent actions, deterministic scenario reset, and
`executed_action` for TP/FP/TN/FN. Metrics are step/event level:

- attack + executed action != allow -> TP
- attack + allow -> FN
- normal + executed action != allow -> FP
- normal + allow -> TN

Reports now include FPR, precision, recall/F1, normal/attack action
distributions, and `action_confusion`.

## Reward Path

`agent/reward.py` still maps:

- attack + block/isolate -> positive detection reward
- attack + flag -> partial positive reward
- attack + allow -> FN penalty
- normal + allow -> normal reward
- normal + flag/block/isolate -> FP/wrong-isolation penalty

The reward logic itself was not the only cause; the stronger bugs were stale
reward config loading, missing attack features, and action mismatch in replay.
`config/reward_v6_logic_fixed.yaml` was added only after those logic fixes.
